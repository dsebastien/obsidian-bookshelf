# 2026-07-17

## Ported two-phase release workflow

- Replaced `.github/workflows/release.yml` with the fixed two-phase design from obsidian-remarkable-sync (proven live with remarkable-sync 1.5.0: Sigstore cert sha == tag commit). The old shared workflow built and attested at the triggering commit, then created the version-bump commit and tag — so the build-provenance attestation was bound to a different commit than the release tag, and the community-catalog review rejected releases with "attestation failed cryptographic verification".
- New design: a `prepare` job (dispatch on a branch) bumps versions, generates the changelog, formats, runs `bun run build` + `bun test` as a release gate, commits, pushes a lightweight tag, then re-dispatches the workflow at the tag ref with `publish=true`. The `publish` job (dispatch-at-tag or bare tag push) builds, attests (`continue-on-error` removed), and creates the release at `github.sha == tag commit`.
- Adopted verbatim: `bun test` kept in the gate (31 tests pass) and `docs/release-notes.md` kept in the `git add` list (`scripts/generate-changelog.ts` generates it here too). Updated `scripts/release.sh`'s workflow description to match the new phases.
