# 2026-11-04

## Fixed missing cover images

Symptom: some books showed a blank cover, both for notes created by an importer and for notes with a local cover in the attachments folder.

Causes:

- The cover was set with `` style.backgroundImage = `url('${coverUrl}')` ``. `getResourcePath` keeps `'`, `(` and `)` unescaped, so any path with an apostrophe (`Sophie's World (book).jpg`) produced invalid CSS and no image. In the author's vault this hit 455 of ~10,500 book notes.
- `resolveCoverUrl` passed the raw value to `adapter.getResourcePath`. A bare file name, a wikilink (`[[x.jpg]]`), an embed, a markdown image, a Windows path (`a\b.jpg`), or a path with the wrong casing produced a URL to a file that does not exist.

Fix:

- New pure module `src/app/view/cover-url.ts` (`parseCoverValue`, `toCssUrl`) with `cover-url.spec.ts`.
- `toCssUrl` emits `url("...")` and escapes `\`, `"` and newlines.
- `resolveCoverUrl` now resolves vault references with `vault.getAbstractFileByPath`, then `metadataCache.getFirstLinkpathDest` (link rules: bare names, case-insensitive), and uses `vault.getResourcePath(file)`. When no file is found it returns `''`, so the view draws the spine instead of a blank cover.
