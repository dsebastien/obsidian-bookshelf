Default covers for books without an image

Design options for issue #15. Each option is pure CSS on a div (no image file, no web font). Use the controls to try the card sizes and aspect ratios of the Bases view options. Hover a book to see the lift effect.

What the plugin does today

When the cover property is empty, or when it points to a vault file that does not exist, the plugin draws a colored block (HSL color from a hash of the title) with the title written vertically in white. When the cover property holds a URL that does not load (404, offline, renamed host), the plugin sets it as background-image anyway, so the book is an empty gray block. That second case is the real "empty spot".

Spine view (aspect ratio 0.25)

The cover switches to a spine layout by a CSS container query when it is narrower than 2:5. No new setting is needed. The left book of each group is the current behavior.

Palettes

The curated palettes hold dark, saturated colors that real bookcloth and leather use. Gold reads well on all of them. The current HSL hash can give light or gray colors where gold foil has no contrast (switch "Colors" above to see it). The same title always gives the same color, because the index comes from the hash that the plugin already uses.

Proposal

Recommendation

Ship option 2 (cloth hardcover) as the new default, and keep the current look as the "Classic" choice, which is the "turn it off" option of the issue. Add options 3, 4 and 6 in the same release, because each one is about 30 lines of CSS on the same DOM. Leave option 5 (art deco) out unless you like it: it is the weakest at small card sizes.

Settings (view options, "Cover" group)

Key Type Default Values
defaultCover dropdown "Cover without image" cloth classic, cloth, leather, library, mixed
authorProperty property "Author property" note.author any property. A list shows the first value plus "et al.", and wikilinks show their display text.
coverFoil dropdown "Foil" gold gold, silver, copper, blind

Rules

  1. The plugin uses a default cover when the cover value is empty, when the vault file is missing, and also when an image URL fails to load (probe with new Image(), then swap the class on error). The last case fixes the gray block.
  2. The title comes from note.title, else from the file name (same as today). The color index and the style for "mixed" come from the existing title hash, so a book keeps its look across views and reloads.
  3. The view sets --longest (the length of the longest word in the title). The title size shrinks for a long word, so a word never breaks in the middle.
  4. The text is real DOM text, clamped to 4 lines for the title and 2 lines for the author. Sizes use container query units, so the cover scales from 50px to 800px. The author and the ornaments disappear under 96px wide.
  5. The spine layout starts when width / height is below 0.4, which is the 0.25 step of the aspect ratio slider. The spine shows the last name of the author only when the title has 16 characters or fewer.
  6. The cover element gets aria-label="Title by Author", so screen readers read it.
  7. No font is bundled. The serif stack falls back to the system serif.

Implementation plan

  1. src/app/view/default-cover.ts: pure functions hashTitle (moved from generateSpineColor), pickCoverColor, pickCoverStyle, formatAuthor, with a spec file.
  2. bookshelf-view.ts renderBook: build the face and spine DOM, set --cover-bg and --label-bg, set data-style, and add the image error probe.
  3. styles.src.css: the CSS of this page (the part under "PROPOSED"), inside @layer bs-components.
  4. view-options.ts: the three new options.
  5. Docs: docs/configuration.md, documentation/Business Rules.md, release notes.
